# otamodem1 实现总结

## 已完成的功能

### ✅ 1. HTTP监听功能
- **实现文件**: `otamodem1.cpp`
- **功能描述**: 
  - 创建TCP Socket服务器
  - 监听8080端口
  - 支持多连接处理
  - 10秒连接超时机制
  - 非阻塞模式支持

### ✅ 2. 接收升级包数据大小
- **实现文件**: `otamodem1.cpp` - `ReceiveFileSize()`函数
- **功能描述**:
  - 支持旧协议：8字节double类型（单位MB）
  - 支持新协议：8字节MB + 1字节type + 8字节bytes
  - 自动检测协议类型
  - 精确解析文件大小
  - 保存到全局变量`g_expectedFileSize`

### ✅ 3. 磁盘空间检查
- **实现文件**: 
  - `mtd_interface.cpp` - `SpatialProcessingFunction()`
  - `otamodem1.cpp` - `CheckDiskSpace()`
- **功能描述**:
  - 清理旧升级文件
  - 清理过期日志文件（20分钟以上）
  - 清理各类系统日志
  - 检查可用空间是否满足要求

### ✅ 4. 接收升级包内容
- **实现文件**: `otamodem1.cpp` - `ReceiveAndWriteFile()`函数
- **功能描述**:
  - 使用20KB缓冲区接收数据
  - 实时写入文件到 `/oemdata/upgrade/update.zip`
  - 检测"end"结束标记
  - 验证实际接收大小与期望大小
  - 防止误判（数据中包含"end"字符串）
  - 返回接收统计信息

### ✅ 5. 解压升级包
- **实现文件**: `upgrade_interface.cpp` - `ota_unzip_file()`函数
- **功能描述**:
  - 清理旧的升级文件
  - 执行 `tar -zxvf` 命令解压
  - **最多重试3次**，确保解压成功
  - 验证四个关键文件存在性：
    - md5.txt
    - mcu_1.bin
    - mcu_2.bin
    - update.zip
  - 删除压缩包释放空间
  - 记录解压时间统计

### ✅ 6. MD5校验
- **实现文件**: `md5_interface.cpp`
- **功能描述**:
  - **CalculateMd5()**: 计算文件MD5值
  - **VerifyFileMd5()**: 验证文件MD5是否与预期匹配
  - **HexStringToBytes()**: 十六进制字符串转字节数组
  - 从md5.txt读取预期MD5值
  - 逐个校验MCU1、MCU2、Tbox文件
  - 校验失败立即返回错误

### ✅ 7. 多线程并行升级 ⭐ 新增
- **实现文件**: `upgrade_interface.cpp`
- **功能描述**:
  - **mcu_upgrade_thread()**: MCU升级线程函数
  - **mpu_upgrade_thread()**: MPU升级线程函数
  - **LordMcuUpgrade()**: MCU升级执行（带重试机制）
  - **LordMpuUpgrade()**: MPU升级执行
  - **DoUpgrade()**: 并行升级协调器
  
**并行升级特性：**
- 使用pthread创建两个独立线程
- MCU和MPU同时执行升级操作
- 升级协调器（UpgradeCoordinator）管理状态同步
- 互斥锁保护共享数据
- 条件变量用于线程通知
- 15分钟总超时保护
- 等待两个线程都完成后统一发送结果

**MCU升级特性：**
- 最多重试3次
- 每次重试间隔5秒
- 5分钟超时保护
- 状态轮询（3秒间隔）
- 记录升级耗时

**MPU升级特性：**
- 单次执行（无重试）
- 10分钟超时保护
- 状态轮询（3秒间隔）
- 进度上报（65% → 100%）
- 记录升级耗时

### ✅ 8. 升级状态管理
- **实现文件**: 
  - `file_interface.cpp` - `SetsloveModemUpgradeStatus()`
  - `otamodem1.cpp` - `SetUpgradeStatus()`
- **功能描述**:
  - 5种状态：IDLE、RUNNING、SUCCESS、FAILED、BACKUP
  - 状态写入 `/oemdata/parameters/SlaveModemUpgradeStatus`
  - 进度写入 `/oemdata/parameters/SlaveModemUpProgress`

### ✅ 9. 升级结果反馈
- **实现文件**: `otamodem1.cpp` - `SendUpgradeResult()`函数
- **功能描述**:
  - 成功发送 "Upgrade Success"
  - 失败发送 "Upgrade Fail"
  - **统一在并行升级完成后发送** ⭐
  - 通过socket返回给客户端

### ✅ 10. 等待下一步指令 ⭐ 新增
- **实现文件**: `upgrade_interface.cpp` - `WaitForNextCommand()`函数
- **功能描述**:
  - 发送升级结果后等待客户端指令
  - 超时时间：120秒
  - 使用select非阻塞等待
  - 支持两种指令：
    - **reboot / reboot_begin**: 重启设备
    - **switch_partition / switch_partition_begin**: 切换分区
  - 收到有效指令后立即执行
  - 超时后自动关闭连接
  
**支持的指令：**
1. **重启指令**（reboot 或 reboot_begin）
   - 调用 `SrTboxSystemReboot("otamodem1", REMOTE_CONTROL_REBOOT)`
   - 执行远程控制的系统重启
   
2. **分区切换指令**（switch_partition 或 switch_partition_begin）
   - 调用 `OtaSwitchAOrBPartition2()`
   - 执行A/B分区切换操作

**等待机制：**
- 使用select系统调用实现非阻塞等待
- 每1秒检查一次是否有新数据
- 总超时时间120秒
- 收到未知指令则忽略并继续等待
- 连接断开或超时则退出等待

### ✅ 11. 时间统计报告 ⭐ 
- **实现文件**: `upgrade_interface.cpp`
- **功能描述**:
  - 记录解压耗时
  - 记录MCU升级耗时
  - 记录MPU升级耗时
  - 输出完整的时间报告
  - 便于性能分析和优化

## 关键技术点

### 1. 协议兼容性
- 同时支持新旧两种协议格式
- 使用select机制检测是否有额外数据
- 50ms超时判断协议类型

### 2. 数据安全
- 文件大小验证：实际接收 >= 期望大小
- 防止"end"字符串误判
- 实时flush确保数据写入
- **MD5完整性校验**

### 3. 资源管理
- Socket安全关闭（CloseSocketSafe）
- 文件句柄及时释放
- 内存缓冲区复用
- **解压后自动删除压缩包**

### 4. 错误处理
- 每个步骤都有错误检查
- 失败时正确设置状态
- 详细的日志记录
- **解压支持3次重试机制**

### 5. 解压优化
- 清理旧文件避免冲突
- 最多重试3次提高成功率
- 验证关键文件确保完整性
- 记录解压时间用于性能分析
- 使用sync确保数据落盘

### 6. MD5校验
- 使用OpenSSL库计算MD5
- 从md5.txt读取预期值
- 逐行校验三个关键文件
- 十六进制字符串转换
- 严格的字节级比较

### 7. 多线程并行升级 ⭐ 新增
- **线程模型**：MCU和MPU独立线程并行执行
- **同步机制**：互斥锁 + 条件变量
- **超时保护**：单个线程超时 + 总监控超时
- **状态管理**：升级协调器统一管理
- **结果汇总**：等待所有线程完成后统一返回
- **时间统计**：记录每个阶段的耗时

### 8. 升级重试机制 ⭐ 新增
- MCU升级最多重试3次
- 每次重试间隔5秒
- 失败后自动进入下次重试
- 达到最大重试次数后返回失败

## 性能优势 ⭐ 新增

### 串行升级 vs 并行升级

**串行升级（传统方式）：**
```
MCU升级（假设3分钟）→ MPU升级（假设5分钟）= 总耗时8分钟
```

**并行升级（新方式）：**
```
MCU升级（3分钟）↘
                  → 总耗时5分钟（取最大值）
MPU升级（5分钟）↗
```

**性能提升：**
- 理论上可节省约37.5%的时间
- 实际提升取决于两个升级的耗时差异
- 最坏情况（两者耗时相同）也能保持原速度
